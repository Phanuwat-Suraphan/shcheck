# การพัฒนาและอัปเดตระบบ

## 1. หลักการสำคัญ

- **ข้อมูลอยู่ใน Google Sheets แยกจากโค้ด** — การวางโค้ดใหม่/อัปเดตเวอร์ชัน ไม่ทำให้ข้อมูลการลงเวลา บัญชีผู้ใช้ หรือการตั้งค่าหายไป
- **ต้นฉบับโค้ดอยู่ใน GitHub** (`src/`) และไฟล์สำหรับวางใน Apps Script อยู่ใน `dist/` (สร้างจาก `src/` อัตโนมัติ)
- **ฐานข้อมูลอัปเดตตัวเอง** — เมื่อ Deploy เวอร์ชันใหม่ ครั้งแรกที่มีคนเปิดหน้าเว็บ ระบบจะเพิ่มชีต/คอลัมน์/ค่าตั้งต้นที่เวอร์ชันใหม่ต้องใช้ให้เอง (ไม่ลบข้อมูลเดิม)

## 2. วิธีที่ง่ายที่สุด: ให้ Claude แก้ให้

1. เปิด Claude Code กับ Repository นี้ แล้วเล่าสิ่งที่ต้องการเป็นภาษาไทย เช่น
   - “เพิ่มประเภทการลา ‘ลาคลอด’ และ ‘ลาอุปสมบท’”
   - “ส่งอีเมลแจ้งผู้อำนวยการเมื่อมีใบลาใหม่”
   - “รายงานรายเดือนให้แสดงเฉพาะครู ไม่รวมเจ้าหน้าที่”
2. Claude จะแก้ไขที่ `src/` → สร้าง `dist/` ใหม่ → รันชุดทดสอบทั้งหมด → push ขึ้น GitHub
3. คุณนำ **3 ไฟล์ใหม่ใน `dist/`** ไปวางทับใน Apps Script แล้วทำ **ขั้นตอนอัปเดต (ข้อ 3)**

## 3. ขั้นตอนอัปเดตโค้ดบน Apps Script (ทุกครั้งที่มีเวอร์ชันใหม่)

1. (แนะนำ) สำรองข้อมูล: เปิดไฟล์ฐานข้อมูล → **ไฟล์ → ดาวน์โหลด → Microsoft Excel (.xlsx)**
2. เปิดโปรเจกต์ Apps Script → วางเนื้อหาใหม่ทับไฟล์ `Code`, `Index`, `Admin` → 💾 บันทึก
3. (ไม่บังคับ) ทดลองก่อนเปิดให้ทุกคน: **Deploy → ทดสอบการทำให้ใช้งานได้ (Test deployments)** → เปิด URL ที่ลงท้ายด้วย `/dev` (เปิดได้เฉพาะเจ้าของ และ **ใช้ฐานข้อมูลจริง** — อย่าทดลองลบ/แก้ข้อมูลจริง)
4. **Deploy → จัดการการทำให้ใช้งานได้ (Manage deployments)** → กด ✏️ **แก้ไข** ที่รายการเดิม → ช่อง **เวอร์ชัน** เลือก **เวอร์ชันใหม่ (New version)** → **Deploy**
   - ⚠️ อย่ากด “การทำให้ใช้งานได้รายการใหม่ (New deployment)” เพราะจะได้ **URL ใหม่** และครูต้องเปลี่ยนลิงก์
5. เปิด URL เดิมหนึ่งครั้ง (ระบบจะปรับฐานข้อมูลให้อัตโนมัติ) แล้วลองเข้าสู่ระบบ/ลงเวลา
6. ถ้าเกิดปัญหา **ย้อนกลับเวอร์ชันเดิม** ได้ทันที: Manage deployments → ✏️ แก้ไข → เลือกเวอร์ชันก่อนหน้า → Deploy

## 4. แก้ไขเล็กน้อยเองใน Apps Script

ทำได้สำหรับการแก้ข้อความ/ค่าคงที่ง่าย ๆ เช่น ชื่อโรงเรียน (`APP` ในไฟล์ `Code`), ประเภทการลา (`LEAVE_TYPES`), ตำแหน่ง (`POSITIONS`) แล้ว Deploy เวอร์ชันใหม่ตามข้อ 3

> ข้อควรระวัง: การแก้ในไฟล์ `dist/` โดยตรงจะ **ถูกทับ** เมื่อนำเวอร์ชันใหม่จาก GitHub มาวาง — ให้บันทึกสิ่งที่แก้ไว้ หรือแจ้งให้นำไปแก้ที่ `src/` ด้วย
> สิ่งที่แก้ได้จากหน้าเว็บอยู่แล้ว (ไม่ต้องแก้โค้ด): พิกัด/รัศมี GPS, เวลาทำงาน, วันทำงาน, วันหยุด, การเปิดรับสมัคร, ระยะเวลาเก็บข้อมูล

## 5. สำหรับนักพัฒนา

```bash
git clone https://github.com/Phanuwat-Suraphan/shcheck.git
```

```bash
cd shcheck
```

1. แก้ไขโค้ดที่ `src/` (ห้ามแก้ `dist/` โดยตรง)
2. ถ้าเปลี่ยนโครงสร้างฐานข้อมูล: เพิ่มคอลัมน์ใน `SCHEMA_` (`src/Database.gs`) — ห้ามเปลี่ยนชื่อ/ลบคอลัมน์เดิม แล้วรัน `node tools/gen-db-doc.js`
3. **เพิ่มเลขเวอร์ชัน** `APP.VERSION` ใน `src/Code.gs` ทุกครั้งที่ปล่อยเวอร์ชันใหม่ (ใช้ตัดสินใจปรับฐานข้อมูลอัตโนมัติ)
4. สร้างชุด 3 ไฟล์และทดสอบ:

```bash
node tools/build-bundle.js
```

```bash
node tests/backend.test.js
```

```bash
GAS_SRC=dist node tests/backend.test.js
```

```bash
node tests/e2e.test.js
```

5. ดูหน้าเว็บบนเครื่องโดยไม่ต้อง Deploy: `node tests/e2e-server.js` แล้วเปิด <http://localhost:8787> (ใช้ตัวจำลอง Apps Script)
6. ผู้ใช้ clasp: `clasp push` จะอัปโหลดโค้ดแบบแยกไฟล์จาก `src/` (อย่าผสมกับชุด `dist/` ในโปรเจกต์เดียวกัน — ใช้แบบใดแบบหนึ่ง)

### ข้อกำหนดของโค้ด
- ฟังก์ชันฝั่ง Server ที่ไม่ต้องการให้ Browser เรียก **ต้องลงท้ายด้วย `_`**
- คำสั่งใหม่ที่ Browser เรียกได้ ต้องเพิ่มใน `getRoutes_()` (`src/Code.gs`) พร้อมกำหนด `roles`
- เขียนชีตผ่าน `appendRecord_ / updateRecord_` ภายใต้ `withLock_()` และบันทึก `writeAudit_()` สำหรับการกระทำสำคัญ
- หน้าเว็บต้อง escape ข้อมูลผู้ใช้ด้วย `esc()` ทุกครั้ง
