# ขั้นที่ 9: การทดสอบระบบและผลการทดสอบ

## 1. วิธีการทดสอบ

ระบบทดสอบอัตโนมัติ 2 ระดับ โดยรันโค้ด **จริงทุกไฟล์ใน `src/`** (ไม่ได้เขียนโค้ดแยกสำหรับทดสอบ):

| ระดับ | เครื่องมือ | สิ่งที่ทดสอบ |
|---|---|---|
| Backend (Server) | `tests/gas-mock.js` — ตัวจำลอง Apps Script (SpreadsheetApp, PropertiesService, CacheService, LockService, Utilities, Session, HtmlService, DriveApp, ScriptApp, UrlFetchApp) + `tests/backend.test.js` | ทุกฟังก์ชันฝั่ง Server ผ่าน `google.script.run` จำลอง (ห้ามเรียกฟังก์ชันที่ลงท้าย `_`, ห้ามคืนค่า Date) และควบคุมเวลา Server ได้ |
| End-to-End (หน้าเว็บจริง) | Chromium (Playwright) + `tests/e2e-server.js` (เรนเดอร์ `Index.html` ผ่าน HtmlService จำลอง + `google.script.run` shim) + **GPS จำลอง** | ผู้ใช้กดหน้าเว็บจริงบนจอมือถือ (Pixel 7) และเดสก์ท็อป ตั้งแต่สมัคร → อนุมัติ → ลงเวลา → ลา → คำร้อง → รายงาน → ส่งออก |

ตัวจำลอง Google Sheets ทำงาน **ตามกฎการรับค่าของ Google Sheets จริง** เพื่อจับข้อผิดพลาดที่พบบ่อยใน Apps Script:
- ข้อความที่ไม่ได้บังคับเป็น Text จะถูกแปลง (`00123` → 123, `2026-11-08` → Date) — ระบบต้องเก็บได้ถูกต้อง
- ข้อความที่ขึ้นต้นด้วย `=` จะถูกตีความเป็นสูตร → ตัวจำลอง **โยน Error** (ตรวจ Formula Injection ทุกการเขียน)
- `setValues` ต้องมีขนาดตรงกับช่วงเซลล์, CacheService จำกัด 100 KB/6 ชม., Script Properties ต้องเป็นสตริง
- ค่าที่คืนให้ Browser ห้ามมี `Date` (Apps Script จะคืน `null`) — ตรวจทุกคำสั่ง

รันเอง: `node tests/backend.test.js` และ `node tests/e2e.test.js` (ต้องมี Node.js 18+ และ Playwright + Chromium)

## 4. ข้อบกพร่องที่พบระหว่างการทดสอบและแก้ไขแล้ว

| ปัญหาที่พบ | การแก้ไข |
|---|---|
| บนมือถือ ข้อความแจ้งเตือน (toast) บังปุ่มออกจากระบบ/ปุ่มในกล่องยืนยัน ทำให้กดไม่ได้ประมาณ 4 วินาที | ย้ายข้อความลงใต้แถบเมนู และไม่รับการแตะ (`pointer-events: none`) |
| ปุ่มดาวน์โหลดไฟล์รายงานถูกเปลี่ยนเป้าหมายไปหน้าต่างแม่เพราะ `<base target="_top">` | ระบุ `target="_self"` ให้ลิงก์ดาวน์โหลด |
| เบราว์เซอร์บางตัวตัดชื่อไฟล์ภาษาไทยทิ้ง (ได้ไฟล์ชื่อ “download”) | ตั้งชื่อไฟล์ส่งออกเป็นภาษาอังกฤษ เช่น `WatSaoHin_Attendance_Monthly_2026-11.xlsx` (ชื่อรายงานภาษาไทยอยู่ในหัวกระดาษ) |
| บนมือถือ ปุ่มลงเวลาอยู่ต่ำกว่าขอบจอ ต้องเลื่อนหา | จัดลำดับใหม่บนจอเล็ก: นาฬิกา → ปุ่มลงเวลา → สถานะวันนี้ → GPS |
| แถบคำอธิบายสัดส่วนสถานะในหน้าภาพรวมตัดคำผิดที่ | ปรับเป็นกริดยืดหยุ่น ไม่ตัดบรรทัดกลางคำ |
| การตั้งรูปแบบคอลัมน์ Plain Text ร่วมกับการนำหน้าด้วย `'` อาจทำให้ Google Sheets เก็บ `'` เป็นข้อความ | ใช้การนำหน้าด้วย `'` อย่างเดียว และฝั่งอ่านตัด `'` ที่หลงเหลือ (ตัวจำลองทดสอบกรณีเลวร้ายนี้) |

## 5. รายการที่ต้องทดสอบเพิ่มบนระบบจริง (UAT) หลัง Deploy

การทดสอบอัตโนมัติรันบนตัวจำลอง จึงต้องยืนยันพฤติกรรมของบริการ Google จริงอีกครั้งหลังติดตั้ง (ใช้เวลาประมาณ 30 นาที):

| # | รายการ | วิธีทดสอบ | ผลที่คาดหวัง |
|---|---|---|---|
| U1 | ติดตั้ง | รัน `SetupSystem()` 2 ครั้ง | 9 ชีต ไม่ซ้ำ, ข้อมูลไม่หาย |
| U2 | Admin คนแรก | ตั้ง Script Properties → `CreateFirstAdmin()` → เข้าสู่ระบบ | ถูกบังคับเปลี่ยนรหัสผ่าน, `BOOTSTRAP_ADMIN_PASSWORD` ถูกลบ |
| U3 | ความเร็วรหัสผ่าน | `BenchmarkPasswordHashing()` | ≤ ~1.5 วินาที (ปรับรอบตามคำแนะนำ) |
| U4 | GPS ใน iframe ของ Apps Script | ลงเวลาด้วย Android (Chrome) และ iPhone (Safari) อย่างละ 1 เครื่อง | เบราว์เซอร์ถามสิทธิ์ตำแหน่ง และบันทึกได้ |
| U5 | รัศมี | กด “ตรวจสอบตำแหน่งของฉัน” ที่ประตูโรงเรียน/อาคารไกลสุด และนอกรั้ว 300 ม. | ในโรงเรียน = เขียว, นอกโรงเรียน = แดง พร้อมระยะห่าง |
| U6 | ข้อความไทยในชีต | ดูชีต Employees/AttendanceLogs | รหัส `0xxx` ไม่หายเลข 0, วันที่/เวลาเป็นข้อความ ไม่มี `'` นำหน้าในค่า |
| U7 | ส่งออก | Export Excel และ PDF รายงานรายเดือน | ไฟล์เปิดได้ ภาษาไทยถูกต้อง มีหัวกระดาษ/ช่องลงนาม; ไฟล์ TEMP อยู่ในถังขยะ Drive |
| U8 | พิมพ์ | ปุ่มพิมพ์รายงาน | หน้าพิมพ์ A4 แนวนอน มีหัวรายงาน |
| U9 | สิทธิ์ | บัญชีครูเปิด DevTools → `google.script.run.withSuccessHandler(console.log).api(sessionStorage.wsh_token,'emp.list',{})` | ได้ `FORBIDDEN` และมี Audit Log `ACCESS_DENIED` |
| U10 | ใช้งานพร้อมกัน | ครู 10 คนกดลงเวลาภายใน 1 นาที | บันทึกครบ ไม่ซ้ำ (บางคนอาจได้ข้อความให้ลองใหม่) |
| U11 | Trigger | ตรวจ Triggers ในโปรเจกต์ | มี `DailyMaintenance` ทุกวัน 02:00 น. |
