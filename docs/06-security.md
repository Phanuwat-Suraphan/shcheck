## 2. การเข้ารหัสรหัสผ่าน — ข้อจำกัดและเหตุผล

Google Apps Script **ไม่มี** bcrypt / scrypt / Argon2 และ `Utilities` มีเพียง SHA/HMAC แบบรอบเดียว ระบบจึง:

1. เขียน **PBKDF2-HMAC-SHA256** (มาตรฐาน RFC 8018 / NIST SP 800-132) ด้วย JavaScript บน V8 พร้อม optimization (pre-computed HMAC state) — ทดสอบแล้วให้ผลตรงกับ Node.js `crypto.pbkdf2Sync` และ test vector ของ RFC 7914
2. ใช้ **100,000 รอบ** เป็นค่าเริ่มต้น (ต่ำกว่าคำแนะนำ OWASP 2023 ที่ 600,000 รอบ เพราะข้อจำกัดความเร็ว CPU ของ Apps Script — การเข้าสู่ระบบต้องไม่ช้าเกินไป)
3. ชดเชยด้วย **Pepper** — กุญแจลับ 256 บิตที่เก็บใน Script Properties แยกจาก Google Sheets: ถ้าไฟล์ Sheets รั่วไหล (เช่น มีคนแชร์ไฟล์ผิด) ผู้ได้ไฟล์ไปไม่สามารถเดารหัสผ่านแบบออฟไลน์ได้หากไม่มี Pepper
4. บันทึกจำนวนรอบไว้ในแต่ละ Hash และ **re-hash อัตโนมัติ** เมื่อผู้ใช้เข้าสู่ระบบหลังเปลี่ยน `PBKDF2_ITERATIONS` → เพิ่มความแข็งแรงภายหลังได้โดยไม่ต้องรีเซ็ตรหัสผ่าน
5. ใช้ `BenchmarkPasswordHashing()` วัดความเร็วบนเซิร์ฟเวอร์จริงแล้วปรับรอบให้ใช้เวลาราว 1 วินาที

**ทางเลือกที่ปลอดภัยกว่า (ถ้าโรงเรียนต้องการในอนาคต):** ใช้บัญชี Google Workspace for Education ของโรงเรียนให้ครูล็อกอินด้วยบัญชี Google (Deploy แบบ “ทุกคนในโดเมน” และใช้ `Session.getActiveUser()`) ซึ่ง Google เป็นผู้ดูแลรหัสผ่าน/2FA แทน — ระบบนี้ใช้ Username/Password ตามข้อกำหนดเพราะครูบางส่วนอาจไม่มีบัญชีโดเมน

## 3. ความเป็นส่วนตัวของข้อมูลตำแหน่ง (PDPA)

- ขอตำแหน่ง **เฉพาะเมื่อผู้ใช้กดปุ่ม** ลงเวลาหรือ “ตรวจสอบตำแหน่ง” — ใช้ `watchPosition` ชั่วคราวไม่เกิน ~15–30 วินาทีเพื่อรอค่าที่แม่นยำ แล้ว `clearWatch` ทันที ไม่มีการติดตามเบื้องหลัง
- มีข้อความแจ้งวัตถุประสงค์และระยะเวลาเก็บรักษา ในหน้าเข้าสู่ระบบ/สมัคร (ต้องยินยอมก่อนสมัคร)/บัญชี
- พิกัดเก็บไม่เกิน `GPS_RETENTION_DAYS` (ค่าเริ่มต้น 365 วัน) แล้ว Trigger รายคืนลบละติจูด/ลองจิจูด คงไว้เฉพาะเวลาและระยะห่าง
- การลงเวลาที่ถูกปฏิเสธเพราะอยู่นอกพื้นที่ บันทึกเฉพาะ “ระยะทาง/ความแม่นยำ” ไม่บันทึกพิกัด
- พิกัดเข้าถึงได้เฉพาะผู้บริหาร/ผู้ดูแลระบบ (ลิงก์แผนที่ในรายงาน) และเจ้าของข้อมูล
- ไฟล์แนบเก็บใน Drive ของบัญชีโรงเรียนแบบไม่แชร์ ดาวน์โหลดผ่านระบบหลังตรวจสิทธิ์เท่านั้น

## 4. ข้อจำกัดด้านความปลอดภัยที่ต้องรับทราบ

1. **การตรวจ GPS ผ่านเว็บไม่สามารถป้องกันการปลอมพิกัดได้ทั้งหมด** — แอป Fake GPS, โหมดนักพัฒนา หรือการแก้ค่าใน Browser สามารถส่งพิกัดปลอมได้ ระบบลดความเสี่ยงด้วยการตรวจรูปแบบค่า, บันทึก Audit/ค่าความแม่นยำ/ระยะห่างทุกครั้ง และให้ผู้บริหารตรวจสอบรูปแบบผิดปกติ (เช่น ระยะห่าง 0 ม. และความแม่นยำเท่ากันทุกวัน) ควรใช้ร่วมกับการกำกับดูแลและมาตรการทางวินัย
2. Session เก็บใน CacheService ซึ่ง Google อาจล้างก่อนหมดอายุได้ในบางกรณี → ผู้ใช้อาจต้องเข้าสู่ระบบใหม่ก่อนเวลา (ไม่กระทบความปลอดภัย)
3. การล็อกบัญชีนับด้วย CacheService ต่อชื่อผู้ใช้ ผู้ไม่หวังดีอาจทำให้บัญชีผู้อื่นถูกล็อกชั่วคราวได้ (Admin ปลดล็อกได้)
4. ผู้ที่มีสิทธิ์แก้ไขไฟล์ Google Sheets หรือโปรเจกต์ Apps Script โดยตรง (เจ้าของบัญชี) สามารถแก้ข้อมูลได้โดยไม่ผ่าน Audit Log — จำกัดผู้ที่รู้รหัสบัญชี Google ของระบบ และเปิด 2-Step Verification ให้บัญชีนั้น
5. Token เก็บใน `sessionStorage` ของแท็บ (ปิดแท็บ = ต้องเข้าสู่ระบบใหม่) ควรออกจากระบบทุกครั้งเมื่อใช้เครื่องสาธารณะ

## 5. Checklist ก่อนใช้งานจริง

- [ ] บัญชี Google ของระบบเปิด 2-Step Verification และรู้รหัสเฉพาะผู้รับผิดชอบ
- [ ] Spreadsheet ฐานข้อมูลและโฟลเดอร์ Drive **ไม่ได้แชร์** ให้ใคร (หรือแชร์เฉพาะผู้ดูแลที่จำเป็น)
- [ ] `BOOTSTRAP_ADMIN_PASSWORD` ถูกลบจาก Script Properties แล้ว
- [ ] Admin คนแรกเปลี่ยนรหัสผ่านแล้ว และมี Admin สำรองอีก 1 คน
- [ ] ตั้งพิกัด/รัศมี/เวลาทำงาน ตรงตามจริงและกด “ยืนยันการตั้งค่า”
- [ ] รัน `BenchmarkPasswordHashing` และปรับรอบ PBKDF2 ให้เหมาะสม
- [ ] แจ้งนโยบายการใช้ข้อมูล GPS แก่บุคลากรเป็นลายลักษณ์อักษร
